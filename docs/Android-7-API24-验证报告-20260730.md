# Android 7.0 / API 24 验证报告

> 范围说明：本文保留 2026-07-30 第一轮 API 24 核心验证记录。随后使用
> `http://192.168.1.11:5173/` 完成了更严格的安全、配置、维护和故障场景测试，
> 并复现三项运行缺陷。当前发布结论、完整矩阵和第二批证据以
> [KioskRelay 严格功能与场景测试报告](./KioskRelay-严格功能与场景测试报告-20260730.md)
> 为准；本文早期证据仍保留用于 WebView 53/119 对照。

## 1. 结论

`v0.4.0-debug` 已在 Android 7.0 / API 24 x86_64 AVD 上完成安装和核心运行流程验证。
在 Chrome `119.0.6045.193` 作为 WebView Provider 时，测试网页可以完整渲染；首启、
配置持久化、展示保护、管理入口、首次进入时的显示策略、开启恢复刷新时的真实断网
恢复，以及 `BOOT_COMPLETED` 自启动均已通过。扩展测试还确认自签名 TLS 被拒绝、
跨 Origin 与 `intent://` 主文档导航被拦截，配置 ZIP 可导入导出。

扩展测试同时稳定复现：

- 关闭网络恢复重载时，失败页面可能被控制器误标记为 Online；
- 从设置返回或执行维护重载后，沉浸式系统栏没有重新隐藏；
- HTTPS 子资源证书失败会把已经渲染的主页面错误升级为全局 Fatal。

源码审计另发现管理员凭据损坏可能被解释成“未设置密码”，从而失败开放管理入口。
这是独立的高风险审计阻断，不计入上述三项真实运行缺陷。

本结论应表述为：

> Android 7 / API 24 Debug 核心流程已在模拟器验证，WebView 119 可渲染指定页面主体；
> 但子资源 TLS 会触发全局 Fatal，且当前仍有三项 API 24 Kiosk 运行缺陷，不能标记
> 生产发布通过。

本轮不能表述为“Android 7 生产发布已全面验收”，原因如下：

- 本次 AVD 镜像自带的 Android System WebView `53.0.2785.124` 无法执行测试目标使用的
  Vite 8 客户端代码，页面白屏。
- Release APK 仅完成构建，尚未签名，也未在 API 24 上安装运行。
- 已有自签名 TLS、直接跨 Origin 和 `intent://` 的人工证据，但真实 HTTP 3xx
  重定向链、`file://`、`content://` 及全部外部协议仍未完成整组设备回归。
- 验证环境是 x86_64 AVD，不等同于目标工业平板或 Android TV 硬件验收。

## 3. WebView 兼容性结果

### 3.1 Android System WebView 53

WebView 53 能加载主文档，页面标题和 `readyState=complete` 均可观察到，但
`@vite/client` 执行时报 `SyntaxError: Unexpected token .`，页面正文为空并表现为白屏。

这说明 KioskRelay 已把主文档交给 WebView，但该 WebView 的 JavaScript 引擎不能执行
当前 Vite 8 客户端代码。不能把这次白屏记录为 KioskRelay 网络加载成功，也不能据此
宣称该 WebView 版本可以运行该客户页面。

### 3.2 Chrome / WebView 119

将 Chrome `119.0.6045.193` 设为 WebView Provider 后，同一页面的标题、布局、文字和
图表区域完整渲染，证明 KioskRelay 的 WebView 展示链路可在 API 24 上运行。

第一轮页面中的业务数据显示为 `--`，当时 Vite 代理对应的本地后端未运行并返回
HTTP 502。扩展测试恢复后端后，主文档和检查的 8 个数据请求最终均返回 HTTP 200。
这证明本轮客户端链路可加载这些请求，但不等于业务数据准确性或服务 SLA 已验收。

最终干净进程重启时，应用 PID 从 `7970` 变为 `8112`，`WebViewFactory` 明确记录加载
Chrome `119.0.6045.193`，页面随后继续完整渲染。该 Provider 在 API 24 上还会输出已由
内部兼容路径处理的 `android.webkit.PacProcessor` 缺类信息；本轮未出现 KioskRelay
`FATAL EXCEPTION`、ANR、`VerifyError` 或 `UnsatisfiedLinkError`，但部署时仍应固定并
回归实际 Provider 包。

### 3.3 部署约束

- Android 7 部署必须固定并验证 WebView Provider；本轮只确认版本 119 可运行该测试页，
  不推断其他版本也一定兼容。
- WebView 53 与当前 Vite 8 开发客户端不兼容。应升级受控设备的 WebView，或让实际生产
  前端输出兼容目标浏览器的代码，再进行完整回归。
- Android 7 仅建议用于受控、可信的内网页面。公网无人值守部署优先选择更高版本 Android。

## 4. 核心功能验收

| 验收项 | 结果 | 说明 |
| --- | --- | --- |
| Debug 安装与启动 | 通过 | APK 可在 API 24 AVD 安装并进入首启流程 |
| 四步首次配置 | 通过 | 语言、品牌、网页/显示、安全/开机配置均可完成 |
| HTTP 风险确认 | 通过 | 未确认时保持 URL 错误；确认后显示明文 HTTP 风险提示 |
| DataStore 进程重启恢复 | 通过 | 进程 PID 变化后配置摘要保持一致并恢复展示 |
| 返回键保护 | 通过 | 展示根页面消费返回，焦点仍在 `MainActivity` |
| 管理员 D-pad 序列 | 通过 | AVD 实际注入 `Up Up Down Down Left Right Left Right OK`，弹出管理员认证；不等同 TV 硬件验收 |
| 横屏、沉浸式全屏、常亮 | 部分通过 | 首次进入通过；从设置/维护返回后系统栏未重新隐藏 |
| 页面失败退避 | 部分通过 | 真实拒绝连接验证 5 秒、10 秒和手动重试；余下档位由自动化覆盖 |
| 真实网络断开与恢复 | 部分通过 | 恢复刷新开启时通过；关闭时存在伪 Online 缺陷 |
| `BOOT_COMPLETED` 自启动 | 通过 | API 24 重启后广播拉起 Debug 应用并聚焦 `MainActivity`；当时 WebView 53 页面仍白屏 |
| WebView 53 测试页 | 不通过 | 主文档加载，但 Vite 8 JavaScript 语法不兼容并白屏 |
| WebView 119 测试页 | 通过客户端加载 | 页面和检查的 8 个数据请求最终返回 HTTP 200；不含业务准确性验收 |
| 自签名 TLS | 通过：正确拒绝 | 取消证书错误并进入 Fatal，显示 `TLS certificate error (3)` |
| HTTPS 子资源 TLS | 不通过 | Open-Meteo Fetch 被正确取消，但整个已渲染主页面被错误升级为 Fatal |
| 跨 Origin / `intent://` | 通过：正确拦截 | 主文档没有离开 KioskRelay，未启动外部 Activity |
| 配置导入导出 | 通过核心路径 | 有效 ZIP 导出/导入、密码保留、未知 schema 拒绝 |
| API 24 Renderer 自动重建 | 不适用 | API 24 没有 `onRenderProcessGone` 平台回调 |

“网络恢复开启时通过”不代表所有网络类型、门户网络、DNS 故障或厂商网络栈均已覆盖。
关闭网络恢复重载时的伪 Online 已列为发布阻断项。

## 6. 本轮未覆盖

以下能力仍只有部分人工证据或主要依赖自动化，不能写成完整设备矩阵已通过：

- 真实 HTTP 3xx 允许/拒绝重定向链；
- `file://`、`content://` 和除 `intent://` 外其他外部协议的完整设备回归；
- Cookie、缓存和网页数据虽执行清理，但未用专用页面逐项断言；
- 配置 ZIP 核心路径已设备端通过；路径穿越、ZIP bomb、坏 CRC 等恶意包仍以 JVM
  测试为主；
- 管理员密码连续失败锁定的完整时间阶梯；
- Release 签名、安装、升级和回滚；
- API 26+ Renderer 退出后的 WebView 重建。
