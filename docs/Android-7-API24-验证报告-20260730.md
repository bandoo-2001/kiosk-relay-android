# Android 7.0 / API 24 验证报告

## 1. 结论

`v0.4.0-debug` 已在 Android 7.0 / API 24 x86_64 AVD 上完成安装和核心运行流程验证。
在 Chrome `119.0.6045.193` 作为 WebView Provider 时，测试网页可以完整渲染；首启、
配置持久化、展示保护、管理入口、显示策略、错误退避、真实网络断开与恢复，以及
`BOOT_COMPLETED` 自启动均已通过本轮验证。

本结论应表述为：

> Android 7 / API 24 Debug 核心流程已在模拟器验证，WebView 119 测试页面渲染通过。

本轮不能表述为“Android 7 生产发布已全面验收”，原因如下：

- 本次 AVD 镜像自带的 Android System WebView `53.0.2785.124` 无法执行测试目标使用的
  Vite 8 客户端代码，页面白屏。
- Release APK 仅完成构建，尚未签名，也未在 API 24 上安装运行。
- 本轮没有形成 SSL 错误、真实重定向链和全部外部协议在 API 24 上的人工验收证据。
- 验证环境是 x86_64 AVD，不等同于目标工业平板或 Android TV 硬件验收。

## 3. WebView 兼容性结果

### 3.1 Android System WebView 53

WebView 53 能加载主文档，页面标题和 `readyState=complete` 均可观察到，但
`@vite/client` 执行时报 `SyntaxError: Unexpected token .`，页面正文为空并表现为白屏。

这说明 KioskRelay 已把主文档交给 WebView，但该 WebView 的 JavaScript 引擎不能执行
当前 Vite 8 客户端代码。不能把这次白屏记录为 KioskRelay 网络加载成功，也不能据此
宣称该 WebView 版本可以运行该客户页面。

### 3.2 Chrome / WebView 119

将 Chrome `119.0.6045.193` 设为 WebView Provider 后，同一页面的标题、布局、文字和
图表区域完整渲染，证明 KioskRelay 的 WebView 展示链路可在 API 24 上运行。

页面中的业务数据仍显示为 `--`，开发者日志记录到 HTTP 502。原因是 Vite 代理对应的
本地后端 `127.0.0.1:8071` 未运行。本轮因此只验证了前端页面渲染，没有验证业务接口、
真实数据和端到端业务正确性。

最终干净进程重启时，应用 PID 从 `7970` 变为 `8112`，`WebViewFactory` 明确记录加载
Chrome `119.0.6045.193`，页面随后继续完整渲染。该 Provider 在 API 24 上还会输出已由
内部兼容路径处理的 `android.webkit.PacProcessor` 缺类信息；本轮未出现 KioskRelay
`FATAL EXCEPTION`、ANR、`VerifyError` 或 `UnsatisfiedLinkError`，但部署时仍应固定并
回归实际 Provider 包。

### 3.3 部署约束

- Android 7 部署必须固定并验证 WebView Provider；本轮只确认版本 119 可运行该测试页，
  不推断其他版本也一定兼容。
- WebView 53 与当前 Vite 8 开发客户端不兼容。应升级受控设备的 WebView，或让实际生产
  前端输出兼容目标浏览器的代码，再进行完整回归。
- Android 7 仅建议用于受控、可信的内网页面。公网无人值守部署优先选择更高版本 Android。

- 跨 Origin 重定向、允许/拒绝重定向链；
- `intent://`、`file://`、`content://` 和其他外部协议的完整设备回归；
- Cookie、缓存和网页数据清理的设备端全流程；
- 配置 ZIP 导入导出及恶意 ZIP 的设备端回归；
- 管理员密码连续失败锁定的完整时间阶梯；
- Release 签名、安装、升级和回滚；
- API 26+ Renderer 退出后的 WebView 重建。
