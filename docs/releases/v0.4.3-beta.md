# v0.4.3-beta — 网页黑屏提示与排查

新增网页预览与展示共用的前置检查：从系统实际 WebView 的默认 UA 识别 Chromium 主版本；低于 80 或无法识别时提示，可打开系统设置或明确继续加载。不使用可伪装的自定义 UA 作为版本依据；系统 WebView 不可用时不给出无效的继续按钮。Chromium 80 只是当前大屏语法的最低警告基线，不代表完整兼容。

修复已复现的问题：只有空容器的 SPA 网页也被判为加载成功，加载提示消失后没有错误反馈。

- 等待 WebView 可绘制回调，并检查页面是否产生文本、媒体或其他可显示控件，再撤掉加载界面。
- 网页加载或空白内容超过 30 秒，显示原生错误、系统 WebView 版本及重试按钮。
- 错误界面增加设置入口；仍经过原管理员密码验证。
- 首次配置的“测试网页”窗口显示具体失败原因。
- 取消离开页面后的检测，避免旧页面回调覆盖新页面状态。

参考：[Android onPageFinished 的渲染限制](https://developer.android.com/reference/android/webkit/WebViewClient#onPageFinished(android.webkit.WebView,%20java.lang.String))。

这个版本修复的是错误反馈和加载成功判定，不能据此断言海信真机黑屏根因已经解决。同一目标网址在 Android 11 / WebView 90 模拟器可显示 Token 页；电视的 WebView 版本和现场错误尚待确认。网页脚本兼容、电视 GPU、目标服务器可达性仍需根据真机诊断区分；纯 CSS 或特殊自定义画面也需单独验收。

没有内置或替换系统 WebView。系统只接受固件允许的提供程序；若需要固定独立内核，应另行集成 GeckoView 并重新验收导航策略、存储、TLS、遥控和渲染。

验证：63 项 JVM 测试、27 项 Android 11 TV 仪器测试通过；Lint 0 错误、53 项警告。包括空白 SPA 不再误报成功、无响应服务器超时、正常页面完成渲染、模拟旧版本提醒的遥控确认和不可用内核提示。Beta 覆盖安装及冷启动后，目标网址显示 Token 输入页。海信现场结果尚未取得。
